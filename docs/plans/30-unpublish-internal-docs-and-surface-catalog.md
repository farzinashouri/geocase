# Unpublish Internal Docs and Surface the Catalog

> **Status: implemented 2026-08-28.**

The GitHub Pages site at `https://farzinashouri.github.io/geocase` publishes **all 260 markdown
files** under `docs/`. There is no exclusion mechanism in the build: `mkdocs.yml` carries only
`not_in_nav`, which suppresses the "not included in the nav" warning but **still builds and serves
every matched page**. Two consequences, in opposite directions.

**Internal content is public.** The full planning log — 35 files including
[`development-plan.md`](development-plan.md), the active plans, and 24 archived ones — is on the
site, with nine of them wired into a "Plans" nav tab. Five internal reports in
`docs/geocase_validate/` (a validation run concluding "don't adopt as a bug-finding tool", a GDAL
issue draft, a pyogrio bug report) are published with *no* nav entry — reachable only by URL, which
is the worse case: they ship without anyone choosing to look. `docs/evidence/2026-fixture-interviews/`
is published too, despite `mkdocs.yml`'s own comment calling it "an internal instrument … not
documentation pages".

**The catalog is buried.** The 187 generated pages (135 cases, 36 risk hubs, 16 format hubs) — the
most valuable user-facing content the project has — are also URL-only. Their two hub pages *are* in
the nav, but as items 1–2 of a six-item **Reference** tab alongside "Codebase Summary" and
"Repository Guide". A visitor gets no signal that a browsable catalog of 135 cases exists.

Intended outcome: the published site contains only user-facing documentation, and the case catalog
is a top-level destination.

## Decisions

| Content | Decision |
|---|---|
| `docs/plans/` + `docs/plans/archive/` (35 files) | **Unpublish.** Stays in the repository, read on GitHub. |
| `docs/geocase_validate/` (5 files) | **Unpublish.** |
| `docs/evidence/2026-fixture-interviews/` (2 files) | **Unpublish.** |
| `docs/design/` (4 files) | Keep published. |
| `docs/contributing/`, `docs/reference/` | Keep published. |
| 187 generated catalog pages | Stay out of the sidebar; hubs promoted to a top-level **Catalog** tab. |

## Phase 1 — Exclude internal content from the build

The mechanism is mkdocs 1.5+ **`exclude_docs`**. mkdocs 1.6.1 is installed, so this needs **no new
plugin and no change to the `[docs]` extra** in `pyproject.toml` — which matters, because
`.github/workflows/pages.yml` installs `.[docs]` and any unlisted plugin turns the deploy red.
Unlike `not_in_nav`, `exclude_docs` removes files from the build, so they are served at no URL.

### 1.1 Add `exclude_docs` to `mkdocs.yml` — done

Replace the `not_in_nav` block (`mkdocs.yml:106-122`) with an `exclude_docs` block for the three
unpublished trees, plus a trimmed `not_in_nav` for the generated pages, which must stay published
but out of the sidebar:

```yaml
# Internal content: kept in the repository and readable on GitHub, but not
# published to the site. `exclude_docs` (unlike `not_in_nav`) removes these
# from the build entirely, so they are not reachable by URL either.
#
#   plans/            - the planning log, incl. the roadmap and superseded plans
#   geocase_validate/ - external validation reports and upstream bug drafts
#   evidence/         - the fixture-interview instrument, not documentation
exclude_docs: |
  plans/
  geocase_validate/
  evidence/

# The generated per-case, per-risk and per-format pages ARE published -- they
# are the catalog -- but reached from the Catalog hub rather than the nav.
# There are 187 of them, regenerated by scripts/generate_catalog_pages.py, so
# listing them by hand would be both unreadable and drift-prone.
not_in_nav: |
  /_generated/catalog/cases/*.md
  /_generated/catalog/risk/*.md
  /_generated/catalog/format/*.md
```

### 1.2 Remove the Plans tab from the nav — done

Delete the `- Plans:` section (`mkdocs.yml:82-92`). Leaving it with `exclude_docs` active makes
`mkdocs build --strict` fail on nine missing nav targets.

Convert each to an absolute GitHub URL

dropping it — the roadmap is genuinely useful, just not as a site page.

## Phase 2 — Promote the catalog

### 2.1 Give the catalog its own top-level tab — done

`navigation.tabs` is enabled, so a top-level nav key renders as a header tab. Move the two catalog
entries out of **Reference** into a new **Catalog** section placed directly after `Philosophy`:

```yaml
  - Catalog:
      - Browse Cases: _generated/catalog/index.md
      - Compare All Cases: _generated/catalog/compare.md
      - Vector Coverage Matrix: _generated/vector-coverage-matrix.md
      - Raster Coverage Matrix: _generated/raster-coverage-matrix.md
  - Benchmark:
      ...
  - Reference:
      - Codebase Summary: reference/codebase-summary.md
      - Repository Guide: reference/repository-guide.md
```

The coverage matrices move too — they are catalog views, not API reference. **Reference** is then
left holding only the two codebase documents, which is what it should always have been.

### 2.2 Link the catalog from the landing page — done

`docs/index.md` should carry an early, explicit link to `_generated/catalog/index.md` ("Browse all
135 cases"). This is the highest-leverage discoverability change in the plan — most visitors never
open a nav tab. Optionally add the same link to the intros of `docs/getting-started.md` and
`docs/case-discovery.md`.

### 2.3 Do not hand-edit the generated pages — done

`scripts/generate_catalog_pages.py` **unlinks every `*.md` under `docs/_generated/catalog/` before
writing**, and `--check` reports any unexpected file as `stale:`. Wording changes to the hub pages
belong in the generator, followed by a regeneration and commit. Nothing in this plan requires that.

## Non-goals

- No new mkdocs plugin, no change to `pyproject.toml`'s `[docs]` extra. `exclude_docs` and
  `not_in_nav` are core mkdocs 1.6 features.
- No exclusion of `docs/design/`.
- No sidebar entries for the 187 individual case pages; they stay hub-reached.
- No files deleted or moved on disk. Only the *published* surface changes.

  `docs/adding-a-case.md:456` was, as the plan suspected, plain text in a "Related docs" list, not a
