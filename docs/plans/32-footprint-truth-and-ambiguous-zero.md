# Plan 32 — Footprint Ground Truth, and the Missing `ambiguous_zero` Case

> **Status: implemented 2026-08-28.** Both phases landed. Phase 2.4 registers
> `ambiguous_zero` in [Plan 27](27-close-plan-26-findings.md) §1.3; the
> `ambiguous_zero`-specific content check stays owed to that plan, as scoped.

## Context

Two loose ends from [Plan 28](28-validate-geocase.md) Phase 1. Both are the same
defect in different places: **the corpus asserts against the wrong reference.**
Phase 1 fixed one instance of this (`hole_center_nodata`) and its outcome notes
recorded the other two rather than widening scope mid-phase. This plan closes
them.

### Finding 1 — three "expected footprints" are GDAL's hull, not ground truth

`footprint_edge_cases/` ships five rasters, each with an
`<case>_footprint.geojson` that `case.yaml` names via `params.expected_footprint`.
The folder's `notes.md` says these were "generated by the GDAL footprint
utility" — which means for three of the five, the fixture is a recording of
`gdal_footprint`'s own simplified/hull output rather than the raster's actual
valid-pixel mask.

Measured in this tree (mask-exact truth derived via `rasterio.features.shapes`
on `dataset_mask()`):

| Case | Committed | Mask-exact truth | Inflation |
|---|---|---|---|
| `all_valid_rectangular` | Polygon 129600.0 | Polygon 129600.0 | **1.000** — identical |
| `hole_center_nodata` | Polygon 115200.0 | Polygon 115200.0 | **1.000** — identical (fixed in Plan 28) |
| `rotated_two_islands` | Polygon 15562.5 | **MultiPolygon** 7875.0 | **1.976×** |
| `nonsquare_diagonal_sparse` | Polygon 27000.0 | **MultiPolygon** 14400.0 | **1.875×** |
| `thin_corridor_shape` | Polygon 38437.5 | Polygon 13750.0 | **2.795×** |

`all_valid_rectangular` is identical only trivially — a full rectangle *is* its
own convex hull — so it needs no change and is not a counterexample.

Three consequences, in increasing severity:

1. **`examples/test_gdal_footprint.py` is tautological for these three.** It
   runs `gdal_footprint`, then asserts the result matches a file that *is*
   `gdal_footprint`'s output, at `max_diff_ratio=1e-10`. That is a regression
   check on GDAL against itself, not a correctness check. It cannot fail for
   the reason the cases were written.

2. **`rotated_two_islands` loses the property it is named for.** The truth is a
   **MultiPolygon** — two disjoint islands. The committed fixture is a single
   Polygon spanning the gap between them. A consumer validating "does my
   footprint code keep disjoint regions disjoint?" against this fixture is told
   that merging them is correct.

3. **`min_rect_ratio` was tuned to the hull and now asserts almost nothing.** A
   convex hull is near-rectangular by construction, so the thresholds pass
   easily. Against the real shapes they do not even hold:

   | Case | `min_rect_ratio` in `case.yaml` | Actual ratio of the truth footprint |
   |---|---|---|
   | `rotated_two_islands` | 0.74 | **0.375** |
   | `nonsquare_diagonal_sparse` | 0.93 | **0.500** |
   | `thin_corridor_shape` | 0.76 | **0.275** |

   `thin_corridor_shape` exists to check that thin geometry survives
   simplification, and is currently validated against a footprint 2.8× too
   large — the exact failure the case is meant to detect would pass.

**Why Plan 28's content gate does not catch this.** `_check_footprint` compares
only *hole counts*. All three hulls have zero holes and all three masks have
zero holes, so they agree. Area, geometry type, and part count are unchecked.
That is the specific gap this plan closes, and it generalises: hole count was
the right check for `hole_center_nodata` and is not sufficient in general.

### Finding 2 — `ambiguous_zero` is referenced but does not exist

Plan 28 removed the phantom `nodata: 0` declaration from `landcover_small`, on
the reasoning that a landcover class of 0 is legitimate and 0-as-both-class-and-
sentinel deserves its own explicit case. The case was never added. The **only**
occurrence of the term in the corpus today is the comment left behind pointing
at it:

```
src/geocase/data/core/raster/landcover_small/case.yaml:31:
  as both a class and a sentinel is the ``ambiguous_zero`` risk and deserves an
```

So the corpus currently names a risk it does not cover, and `landcover_small`'s
own `behavioral_goal` promises a case that is not there.

Note the tension with [Plan 27](27-close-plan-26-findings.md), which owns the
`risk_types` vocabulary problem (111 terms over 135 cases, 75 used exactly
once). Adding a term used by one case is normally the pattern to avoid. It is
justified here because the term is *already referenced* and because
zero-as-sentinel is a real and common failure mode — but the new case must
register the term in whatever vocabulary Plan 27 lands, not float free.

### Intended outcome

1. Every footprint fixture states plainly whether it is ground truth or a
   recorded consumer behaviour, and the example asserts the divergence between
   them instead of comparing GDAL to itself.
2. The content gate checks footprint *shape*, not just hole count.
3. `ambiguous_zero` is a real case, and no case description references
   something that does not exist.

## Phase 1 — Footprint ground truth

### 1.1 Strengthen the content gate first (TDD) — **done**

The gate must be able to see this class of defect before any fixture moves,
or the fix is unverified.

**Failing test** in `tests/unit/test_case_content.py`: build a raster with two
disjoint valid blobs, hand the checker a declared footprint that is their
convex hull (one polygon, no holes — so the *existing* hole-count check
passes), assert the checker reports an error naming `expected_footprint` and
the area divergence. Watch it fail.

Then extend `_check_footprint` in `src/geocase/catalog/content.py` beyond hole
count, comparing the declared footprint to the mask-derived truth on:

- **part count** — a MultiPolygon truth must not be declared as a single
  Polygon (this is `rotated_two_islands`);
- **area**, within a tolerance;
- hole count (already present).

Reuse `assert_footprint_similar_to_expected` from
`src/geocase/assertions/footprint.py` where it fits, per Plan 28's rule that
the gate and the user-facing assertions are the same code.

**This gate change makes the three cases go red**, which is the point — the
same "observed red before the fix" discipline Plan 28 Phase 1 followed.

### 1.2 Split the two meanings into two files — **done**

Rename so the filename carries the claim, and generate the truth file:

- `<case>_footprint_truth.geojson` — **new**, mask-derived, emitted by
  `scripts/generate_raster_fixtures.py` from the same array as the raster, via
  the existing `emit_footprint` mechanism added in Plan 28 (currently used only
  by `hole_center_nodata`). Cannot drift by construction.
- `<case>_footprint_gdal_hull.geojson` — the existing committed file, renamed.
  Keeps the recorded-behaviour baseline, so a future change in GDAL's hull
  behaviour is still detectable. **Not** deleted: deleting it would trade one
  blind spot for another.

`hole_center_nodata` already has a mask-derived footprint from Plan 28 and needs
only the rename to `_truth`. `all_valid_rectangular`'s two files would be
byte-identical; emit only `_truth` for it and note why.

### 1.3 Metadata — **done**

In each `case.yaml` under `footprint_edge_cases/`:

- `params.expected_footprint` → points at the `_truth` file. This is the key
  the content gate reads, so the gate checks against ground truth.
- `params.recorded_gdal_footprint` → new, points at the `_gdal_hull` file where
  one exists. Named for what it is: one consumer's recorded output.
- `params.min_rect_ratio` → **re-derived from the truth geometry**, not carried
  over. The current values (0.74 / 0.93 / 0.76) were fitted to the hull; the
  truth ratios are 0.375 / 0.500 / 0.275. Set thresholds slightly below the
  measured values, and record in `notes.md` that they describe genuinely
  non-rectangular shapes.

`docs/adding-a-case.md` (lines ~249–250) shows `expected_footprint` /
`min_rect_ratio` in its worked example and must be updated in the same change.

### 1.4 Rewrite the example to assert the divergence — **done**

`examples/test_gdal_footprint.py`'s parametrized
`test_gdal_footprint_edge_cases_against_real_expected_data` currently asserts
GDAL ≈ committed-file at `1e-10`. Restructure to the shape Plan 28 already
established with `test_gdal_footprint_fills_interior_nodata_void`:

- GDAL's output matches `_gdal_hull` (recorded behaviour — the regression check,
  still exact);
- GDAL's output **diverges** from `_truth` for the three inflated cases, with
  the divergence asserted in the direction observed (hull ⊇ truth, area
  strictly greater, disjoint parts merged for the two MultiPolygon cases);
- for `all_valid_rectangular`, GDAL matches truth exactly — the control that
  shows the divergence is a property of the shapes, not of the harness.

This turns the example from "GDAL still does what GDAL did" into a demonstration
of *what a footprint consumer gets wrong and where* — which is the thing geocase
exists to show.

### 1.5 Regenerate the gated artifacts — **done**

Checksums, catalog pages, `case-index.yaml`, both coverage matrices. Confirm
the content gate is green afterwards and was red before 1.2.

## Phase 2 — The `ambiguous_zero` case

### 2.1 Failing test first — **done**

Add to `tests/unit/test_case_content.py` (or the raster family tests): the case
id resolves, loads, and its declared `nodata` value is present in the pixel data
**and** is also a semantically meaningful class value. Watch it fail — the case
does not exist.

### 2.2 The case — **done**

A small single-band uint8 landcover-style raster where **0 is simultaneously a
valid class and the declared nodata sentinel**:

- generated by `scripts/generate_raster_fixtures.py` (under the regeneration
  gate — no hand-committed payload, per Plan 28's lesson);
- real 0 pixels present, so Plan 28's `expect_nodata` content check has
  something to verify and the case is not inert;
- `risk_types: [ambiguous_zero, nodata_ignored]`;
- `notes.md` stating the ambiguity plainly: a consumer masking `data == nodata`
  silently deletes a legitimate class, and there is no way to tell the two
  apart from the file alone. That indistinguishability *is* the case.

Sibling of `landcover_small`, which is the same scene with the ambiguity
removed — the pair is the useful artifact, so cross-reference both ways.

### 2.3 Close the dangling reference — **done**

Update `landcover_small`'s `behavioral_goal` to name the new case id rather than
the bare term, so no description points at something that does not exist.

### 2.4 Vocabulary registration — **done**

Register `ambiguous_zero` in the `risk_types` vocabulary owned by
[Plan 27](27-close-plan-26-findings.md), including the content-gate check that
enforces it (Plan 27's row already requires each entry to name its enforcing
check). Do **not** fork that work into this plan.

## Outcome (2026-08-28)

Both phases implemented. What the plan got right, and what it did not:

**Confirmed exactly as written.** The five measured areas, the three inflation ratios, and the
three truth `min_rect_ratio` values (0.375 / 0.500 / 0.275) all reproduced in this tree. The
strengthened gate was observed red on **exactly** the three named cases and nothing else, then
green after 1.2–1.3.

**Differed from the plan:**

1. **`nonsquare_diagonal_sparse`'s truth has 8 parts, not 2.** The plan called it a
   MultiPolygon without saying how many. The valid pixels are a diagonal run touching only at
   corners, so the mask-exact geometry is eight disjoint squares — the hull is 1.875× the area
   *and* collapses eight regions into one. The example's `_HULL_INFLATED` map records the real
   part count per case.
2. **`hole_center_nodata`'s `min_rect_ratio` was also fitted to the hull.** The plan listed
   three stale thresholds; there were four. It declared `0.98` against a truth ratio of
   `0.8889`. Re-derived to `0.85` along with the others.
3. **`all_valid_rectangular` got a `_truth` file and no `_gdal_hull` file**, as 1.2 specified —
   the two would be byte-identical. Its `case.yaml` therefore has no
   `params.recorded_gdal_footprint` key, and the example branches on that key's absence rather
   than on a case-id list.
4. **Three tests in `tests/unit/test_assertions.py` read the renamed fixtures by path** and had
   to move with them. The plan's compatibility table did not anticipate this; it is still
   correct that no public surface changed. The rectangularity test there now runs against truth
   (ratio 0.375 vs a 0.999 threshold) rather than the hull, so it still fails for the right
   reason.
5. **Adding a case moved the count off 135**, failing `validate_catalog.py`'s `_COUNT_CLAIMS`
   gate in seven files — the same chain [Plan 27](27-close-plan-26-findings.md) §1.1 warned
   about. All seven bumped to 136.

**Both required proofs were performed.** Pointing `expected_footprint` at the `_gdal_hull` file
for `rotated_two_islands` made `validate_case_content.py` fail naming the part-count *and* area
divergence, and made the example's divergence test fail. Both restored.

**Verification, all green under the conda env:** every `--check` generator, both content gates,
`pytest tests` (1772 passed, 37 skipped), `pytest examples` (1189 passed, 36 skipped,
43 xfailed), `ruff format`/`check`, `mypy src`, `mkdocs build --strict`.
